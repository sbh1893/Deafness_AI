# 파이프라인 테스트 결과 요약

- 테스트 날짜: 2026-08-24
- 데이터: TaL80 샘플 데이터 (`Deaf_AI/TaL_Corpus_Sample/samples/core`, 화자 80명 × 발화 1개 = 총 154개 발화)
- 실행 환경: Google Colab (GPU: T4)
- 실행 노트북: `Deafness_AI_04_audio_to_tongue_실행결과.ipynb` (이 폴더 안에 실행 결과가 그대로 저장되어 있습니다. Colab이나 Jupyter로 열면 각 셀의 출력을 바로 확인할 수 있습니다.)

## 무엇을 테스트했나

목소리 녹음만 듣고 그 순간 혀가 입안 어디에 있었는지를 AI가 추정하는 파이프라인입니다. 청각장애인의 발음 학습을 돕기 위해, 화면에 "지금 혀 위치가 이렇습니다"를 보여주는 기능의 핵심 모델입니다. 5단계 중 마이크가 필요한 5단계(로컬 PC 전용)를 제외한 1~4단계를 Colab에서 실행했습니다.

## 결과

| 단계 | 내용 | 결과 |
|---|---|---|
| 1단계 | 데이터 전처리 (오디오 → 멜 스펙트로그램, 초음파 → PCA 3차원 축소, 화자 단위 train/val/test 분리) | 성공. 154개 발화 → train 123 / val 16 / test 15로 저장. PCA 설명 분산 29.0% |
| 2단계 | Ridge 회귀 베이스라인 (문맥 없이 한 순간의 소리만 보고 예측) | 성공. 테스트셋 상관계수 r = 0.483 / 0.092 / 0.205 (3개 축) |
| 3단계 | 1D CNN 모델 학습 (앞뒤 소리 흐름을 함께 보고 예측) | 성공. GPU로 30epoch 학습, loss 우하향. 검증셋 상관계수 r = 0.773 / 0.196 / 0.206 |
| 4단계 | 화자독립 최종 평가 (한 번도 안 본 화자 8명, 발화 15개로 Ridge vs CNN 비교) | 성공. CNN이 3개 축 전부에서 Ridge보다 상관계수가 높음 (문맥을 보는 게 실제로 도움이 됨을 확인) |

### 4단계 상세 비교 (화자독립 테스트셋)

| 조음 파라미터 | Ridge r | CNN r | Ridge RMSE | CNN RMSE |
|---|---|---|---|---|
| 1번 축 (혀 전후 위치) | 0.483 | **0.568** | 416.8 | 438.5 |
| 2번 축 (혀 고저 위치) | 0.092 | **0.193** | 316.0 | **301.2** |
| 3번 축 | 0.205 | **0.359** | 150.1 | **148.9** |

r 값은 0~1 사이로, 1에 가까울수록 예측이 실제와 잘 맞는다는 뜻이고 0에 가까우면 거의 무작위 수준이라는 뜻입니다.

## 쉬운 설명

- 파이프라인 자체는 에러 없이 처음부터 끝까지 정상 작동했습니다.
- "앞뒤 소리 흐름을 같이 보는 CNN 모델"이 "그 순간 소리만 보는 단순 모델(Ridge)"보다 세 지표 모두에서 더 잘 맞혔습니다 → 시간적 문맥이 실제로 도움이 된다는 뜻.
- 혀의 앞뒤 위치(1번 축)는 비교적 잘 따라갔지만(r 최대 0.77), 나머지 두 축은 아직 감을 잘 못 잡는 편입니다.
- 지금 쓴 데이터는 화자당 발화가 딱 1개뿐인 "샘플" 데이터라서 AI가 배울 정보가 매우 적었습니다. 그런데도 어느 정도 신호가 있다는 게 확인됐고, 무엇보다 코드/파이프라인이 정상적으로 돌아간다는 게 이번 테스트의 핵심 성과입니다.
- 의미 있는 성능을 보려면 화자당 발화 수가 많은 더 큰 데이터로 다시 돌려봐야 합니다.
